# Contributing to precursor-kanban

Thanks for helping out. This is a plugin, not an application: it only ever runs
inside a Precursor process, and most of what is unusual here follows from that.

## Setting up

```bash
make hooks   # once — blocks committing proxy-resolved lockfiles
make sync    # uv sync + npm ci + build the frontend bundle
make check   # every gate CI runs
```

`make sync` builds the frontend because the Python package has no `web/`
directory until it does. A checkout that skips it advertises the section and
then has nothing to render for it.

## The two contracts

Everything this package is allowed to rely on comes through two versioned
surfaces. Neither is "the host's internals".

| Side | Surface | Declared in | Version |
| --- | --- | --- | --- |
| Python | `precursor.plugin_api` | the host's wheel | `PLUGIN_API_VERSION` |
| Frontend | `@precursor/host` | `web/types/precursor-host.d.ts` (ours) | `HOST_API_VERSION` |

If you find yourself importing `precursor.backend.something` in `src/`, stop:
that is either a gap in `plugin_api` worth raising upstream, or a sign the change
belongs in the host. (The *tests* import backend internals freely — they are
booting a real app, which is the point.)

### Tracking the host SDK

`web/types/precursor-host.d.ts` is a hand-written declaration of
`@precursor/host`. It exists because nothing is ever installed for that
specifier — an import map supplies it at runtime — so TypeScript has nothing to
resolve. In the monorepo the host papered over this with a `paths` mapping onto
its own source; out of tree we write the contract down instead.

Two rules keep it honest:

- **Declare only what we import.** A narrow shim is one you can keep true; a
  complete transcription of the host's runtime is one that silently rots.
- **The host is right.** If a signature here disagrees with
  `frontend/src/host/runtime.ts` upstream, this file is wrong. Fix it here and,
  if the host's own type was the problem, upstream too.

When you start using a new host export, widen the shim in the same change.
`npm --prefix web run typecheck` is what catches the mismatch.

## Testing against the host

The tests boot a **real** Precursor via `create_app()` and let it discover this
plugin through its entry point. That is deliberate: it is the only way to prove
the wiring — entry point, router mounting, the shared GitHub guards — still holds
against a host we no longer release in lockstep with.

The host is resolved from **git `main`**, not PyPI, declared in
`[tool.uv.sources]`. That is not a taste for bleeding edge: `precursor.plugin_api`
landed after the host's `2026.7.0` release, so a suite resolved from PyPI cannot
even import. `uv.lock` pins the exact commit, so it stays reproducible.

Two consequences:

- **A weekly CI job (`host-compat`) re-resolves the host** and runs the suite
  against Precursor's current `main`, ignoring the lockfile. It is how we learn
  the contract moved before users do. If it goes red, the host changed —
  read its diff before changing anything here.
- **When a released host exposes `plugin_api`**, add a PyPI floor to the `dev`
  group and decide whether to keep the git source as a second CI leg.

`tests/conftest.py` reproduces the isolation the host's own root `conftest.py`
used to provide: a throwaway database and data directory, no Copilot CLI spawn,
no live model calls — and it configures logging, which is load-bearing rather
than cosmetic (see the comment there).

## Lockfiles

`uv.lock` and `web/package-lock.json` are regenerated by CI, never locally.
Corporate mirrors rewrite artifact URLs *and* weaken the integrity metadata (npm
`sha512` → `sha1`, uv loses `size`/`upload-time`), which survives review as an
innocuous URL diff.

```bash
gh workflow run relock.yml --ref <your-branch>   # pushes the fix back to it
```

Day to day, avoid re-resolving: `export UV_FROZEN=1`, and `npm ci` rather than
`npm install`. `make hooks` installs a pre-commit guard, and CI runs the same
check (`scripts/check_lockfiles.py`).

## Style

- Python 3.12+, `from __future__ import annotations`, async wherever the network
  or database is touched. `ruff` and `mypy --strict` are enforced.
- React function components with named exports; the app's theme tokens
  (`bg-surface`, `text-muted`, …) rather than raw colours, so the board follows
  the user's theme.
- Comments explain **why**, not what. Don't add docstrings to code you didn't
  touch.
- Hover hints use `data-tooltip="…"`, never `title` — the host styles and clamps
  them. An icon-only control still needs an explicit `aria-label`.

## Releasing

See [RELEASING.md](RELEASING.md). Short version: update `CHANGELOG.md`, push a
`v<CalVer>` tag, and the **Publish** workflow builds and uploads to PyPI through
Trusted Publishing.
